# W04 Retrospective

## Strongest technical result

The Week 3 fine-tuning and RAG work is the strongest result of the four weeks, mainly because it's the most complete: a real QLoRA/DPO ablation across three configurations on a live GPU (not a simulated or dry-run comparison), a working FAISS retrieval pipeline evaluated on held-out queries, and an independent safety classifier evaluated on a labeled test set that had no role in designing the classifier itself. The numbers hold up under scrutiny: config B's eval loss (0.0082) is genuinely the best of the three, hit@1 retrieval accuracy (84.6%) is honestly reported alongside the one query it misses, and the safety checker's zero false negatives on ESCALATE came with an explicit accounting of the false-positive cost that produced. Week 2's edge classifier is close behind on rigor (the same held-out-test-split discipline, the same refusal to round off an inconvenient result), but Week 3 is where the methodology got tested hardest, including a real GPU debugging problem (a dtype mismatch inside `trl` itself) that had no answer in any tutorial and needed the actual library source read to resolve.

## How this extends the resume

This directly extends the Psychologist Agent project: same DPO+QLoRA fine-tuning approach, same FAISS RAG pattern, same principle of keeping a safety check independent of the model it's checking, now applied to a second domain (eldercare dialogue instead of general supportive conversation) and evaluated with the same rigor. It also extends the AURA AIoT project in the other direction: Week 2's edge classifier took AURA's sensor-classification idea and added the deployment-engineering half AURA never needed (quantization, latency benchmarking, a real accuracy-latency trade-off with a stated recommendation). Between the two, this internship adds "did this at production standard on a second, independently verifiable domain" to both of the strongest technical projects already on the resume, rather than just repeating them.

## Job titles this work supports

**Applied ML Engineer** and **ML Engineer (LLM / Applied Research)** are the most direct fits: the Week 3 track is a complete fine-tune-plus-retrieval-plus-safety-evaluation pipeline, the kind of work that shows up in job descriptions asking for QLoRA/DPO experience, RAG system design, and eval methodology, not just model training in isolation. **Edge / Embedded ML Engineer** is the second fit, supported by Week 2's quantization and latency-benchmarking work, though that track is a smaller share of the four weeks than the LLM track. The common thread across both is the same: build something, measure it honestly on a held-out set, and write down what the numbers actually mean rather than what would be convenient for them to mean.
